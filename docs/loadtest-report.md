# 压测报告（阶段 8）

> 目标（需求 §4）：1000 并发混合场景（登录/列表/上传/下载/预览）下，错误率 0%、无 5xx、P99 < 500ms。

---

## 1. 测试环境（单机，非生产）

| 项 | 值 |
|---|---|
| 机器 | Apple Silicon Mac（8 性能核） |
| 应用 | Spring Boot 3.3.5 + Tomcat（内嵌）+ MyBatis + MySQL 8（Docker 容器） |
| 压测工具 | Apache JMeter 5.6.3 |
| 部署 | **应用 + MySQL + JMeter 同一台机器**（压测进程本身也抢 CPU） |

> 说明：这是「单机三合一」的极限压测，生产上应用、数据库、压测机分离，瓶颈分布会完全不同。

## 2. 测试场景与方法

- 1000 线程、ramp-up 1s（**近乎同时启动，制造真实 1000 并发峰值**）、每线程 1 次循环。
- 每线程顺序执行 6 类请求：`登录 → 列表 → 下载 → 预览 → 上传 → 配额`。
- 共 **6000 请求**。预置 100 个测试用户（BCrypt 登录）+ 各 1 个文件（供下载/预览）。
- 上传文件名按线程号唯一，避免唯一约束误伤；JSON 接口断言 `"code":0`，下载/预览断言 HTTP 200。

## 3. 结果（两轮线程池调优对比）

### 总览

| 轮次 | 线程池 maxThreads | 请求数 | 错误率 | 5xx | 吞吐 | 总 P99 |
|---|---|---|---|---|---|---|
| ① | 200 | 6000 | **0%** | **0** | ~302 req/s | 14206 ms |
| ② | 800 | 6000 | **0%** | **0** | ~272 req/s | 15810 ms |

### 分接口 P99（毫秒）

| 接口 | ① 200 线程 | ② 800 线程 | 变化 |
|---|---|---|---|
| 上传 | 1045 | 3446 | 变差 |
| 下载 | 9459 | **4311** | 明显变好 |
| 列表 | 11905 | **6507** | 明显变好 |
| 登录 | 14616 | 16773 | 变差 |
| 预览 | 2932 | 3713 | 变差 |
| 配额 | 995 | 2361 | 变差 |

## 4. 关键结论

1. **连接不阻塞、不失败**：两轮 1000 真并发、6000 请求，**错误率 0%、无 5xx、无连接拒绝**。这印证了 NIO 的核心——「连接多 ≠ 线程多」：1000 个连接由 200~800 个工作线程处理，请求排队但不被拒绝（`maxConnections=10000` 兜住连接数）。

2. **P99 未达 500ms，瓶颈是单机硬件**：登录 P99 高达 14~17s。本质原因：**BCrypt 登录是 CPU 密集**，1000 个 BCrypt（每个约 50ms）≈ 50 秒 CPU 时间，8 核机器理论上就需 ~6 秒墙钟，加多少线程也压不下去；上传/下载还叠加本地磁盘 I/O。

3. **线程池不是越大越好（重要面试点）**：200→800 后，**I/O 密集的下载/列表 P99 显著下降**（下载 9.5s→4.3s、列表 11.9s→6.5s，更多线程重叠 I/O 等待），但 **CPU 密集的登录反而变差**（14.6s→16.8s，上下文切换开销）。→ 线程数要按「CPU 密集 vs I/O 密集」的工作负载比例来定，不是线性加。

4. **200 线程其实更贴近「CPU 密集 + 轻 I/O」场景**，800 线程更适合「下载/列表为主」的读多写少网盘。生产选型要压测决定，不能拍脑袋。

## 5. 与验收目标的差距（诚实说明）

| 目标 | 结果 | 达成 |
|---|---|---|
| 错误率 0% | 0% | ✅ |
| 无 5xx / 无超时 | 无 5xx、无连接拒绝 | ✅ |
| P99 < 500ms | 14~16s | ❌（单机 CPU/磁盘瓶颈） |

**为什么 P99 达不到，以及如何达到：**

- 「1000 并发」若理解为「1000 人同时在线」（现实语义），实际并发请求通常只有几十到一两百，P99 完全可 < 500ms；本测试是「1000 个请求同时打进来」的极限突发，比现实严苛得多。
- 真要 1000 并发 P99<500ms，需要：① 加核/分布式部署；② BCrypt 降 cost 或登录结果缓存（牺牲一点安全换延迟）；③ 文件走对象存储/CDN 卸载磁盘 I/O；④ 数据库读写分离。
